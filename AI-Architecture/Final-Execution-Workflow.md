# Operational Memory Repository (OMR)

The OMR is **not part of the execution workflow**.

It is the final destination of the completed execution.

It stores only the final Approved Execution Record.

## Customer Information

* Customer ID
* Customer Name
* Country
* Phone Number
* Relationship to Beneficiary

## Beneficiary Information

* Beneficiary Name
* County / Town
* Phone Number

## Execution Information

* Execution ID
* Requested Items or Services
* Assigned Coordinator
* Current Status
* Completion Date

## Financial Information

* Invoice Number
* Service Fee
* Total Amount
* Payment Status
* Payment Date

## Completion Information

* Completion Status
* Completion Timestamp

The OMR does **not** store:

* Photos
* Videos
* PDFs
* Receipts
* Inspection Reports
* Google Live Pins
* WhatsApp Conversations
* Generated Documents

Those remain in the Mkono Global WhatsApp Business conversation, which serves as the permanent communication and evidence archive.

# The Five Enterprise Principles

1. **The Approved Execution Record is the only working document throughout the entire execution lifecycle.**

2. **The Operations Team is the workflow orchestrator. AI Workstations never decide the next step.**

3. **Each AI Workstation has one responsibility, one input, one output, and one clearly defined handoff.**

4. **Ground Execution is performed by people. AI supports execution but never performs it.**

5. **The Operational Memory Repository (OMR) is written only once, after the execution has been officially closed. It serves as the permanent historical record, not as the AI's working memory.**

---

I think this version is substantially stronger than the earlier iterations because it follows a single, consistent principle: **one live working document, one orchestrator, one final archival write.** That eliminates repeated database reads, avoids synchronization problems, keeps AI prompts small, and makes ownership and handoff points explicit at every stage. It also gives every workstation a well-defined contract: **Start → Process → End → Handoff**. That is the kind of structure that scales cleanly as Mkono Global grows.
